適合先評估的問題

正式報價或系統導入通常很複雜。早期更適合先看：詢價資料進來後，是否能被整理成清楚、可追蹤、可人工審查的案件。

資料分散

Email、圖面、Excel、STEP、DWG 或客戶平台訊息分散，整理成內部案件前需要人工確認。

缺漏常見

數量、材質、revision、交期、表面處理或附件版本不完整，導致報價前反覆追問。

交接不透明

業務、助理、估價與工程人員都看過一部分，但缺少一份可 review 的完整 intake case。

Before / After

Before

  • 逐一打開信件、圖面與附件。
  • 手動複製料號、材質、數量與交期。
  • 缺漏問題分散在信件往返或個人筆記。

After

  • 核心欄位整理成 intake case。
  • 缺漏與衝突集中標示。
  • 人員再判斷價格、成本與正式回覆。

後續可延伸的只讀比對

如果詢價資料需要確認是否為重複詢價、圖面改版或既有料號，早期不需要登入 ERP。較安全的做法，是先用一份最小欄位的參考表做只讀比對。

參考表可包含

  • 客戶代稱或客戶代碼。
  • 料號或圖號。
  • 上次 revision、詢價日期與報價狀態。
  • 內部負責人或下一步狀態。

只作人工審查提示

  • 可能是新案。
  • 可能是重複詢價。
  • 可能是圖面改版。
  • 仍需由人員確認，不做最終判定。

評估範圍與資料邊界

目前先以小範圍流程評估為主。第一次聯絡不需要提供機密圖面、客戶資料、價格、成本或 ERP 匯出；也不做 AI 自動報價、ERP 寫入、自動寄正式報價或正式上線 SLA / 正式服務保證。若後續需要比對既有紀錄，會先以客戶提供的只讀參考表處理，不要求 ERP 登入、API 或寫入權限。

5 題流程自評

如果這些答案目前要靠人工翻信件或圖面才知道，詢價資料 intake 可能值得先整理。

  1. 每月大約收到多少 RFQ / 詢價？
  2. 詢價資料主要來自 Email、圖面、Excel、CAD/STEP、客戶平台，還是其他？
  3. 誰負責先整理料號、材質、數量、交期與附件？
  4. 一封詢價整理到可報價 review，大約需要幾分鐘？
  5. 最常缺的是數量、材質、圖面 revision、交期，還是其他？
